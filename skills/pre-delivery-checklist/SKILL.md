# 納品前チェックリスト

コーディング完了後、納品・公開前の最終確認に使う。実際のコードやURLを渡された場合は、可能な範囲で個別に指摘し、確認できない項目（実機での操作確認など）はチェックリストとして提示する。

## 1. マークアップ・アクセシビリティ

- [ ] 見出し（h1〜h6）の階層が飛んでいないか
- [ ] 画像に適切な`alt`属性が入っているか（装飾目的の画像は`alt=""`）
- [ ] フォーム要素に`label`が正しく紐付いているか
- [ ] リンクのテキストだけで遷移先が分かるか（「こちら」だけ等になっていないか）
- [ ] コントラスト比が十分か（特に薄いグレー文字、ボタン）

## 2. レスポンシブ・表示崩れ

- [ ] SP/タブレット/PCの主要ブレークポイントで崩れがないか
- [ ] 極端に長い日本語テキスト・英単語で崩れないか
- [ ] 画像の縦横比が`aspect-ratio`等で保持されているか

## 3. パフォーマンス

- [ ] 画像が適切に圧縮・リサイズされているか（表示サイズ以上の解像度で書き出していないか）
- [ ] 遅延読み込み（`loading="lazy"`）が主要な画像に設定されているか
- [ ] 不要なCSS/JSが読み込まれていないか
- [ ] Prettier/ESLint/Stylelintを導入している案件では、`format:check` / `lint` がエラーなしで通るか（code-formatting-lintスキル参照）

## 4. SEO・メタ情報

- [ ] 各ページに`title`・`meta description`が設定されているか（使い回しになっていないか）
- [ ] OGP（`og:title` `og:image`等）が設定されているか（可能ならSNSのシェアデバッガーで表示確認）
- [ ] 開発中に付けた`noindex`が本番公開時に外れているか（静的サイトの場合。WordPressは項目6参照）
- [ ] `sitemap.xml`・`robots.txt`が設置されているか（seo-meta-implementationスキル参照）
- [ ] `favicon`が設定されているか
- [ ] 404ページが用意されているか

## 5. リンク・機能

- [ ] 内部リンクにリンク切れがないか
- [ ] 外部リンクに`target="_blank"`を使う場合、`rel="noopener"`が付いているか
- [ ] フォームの送信確認（バリデーション、確認画面（ある場合）、完了画面、通知メールの受信まで）
- [ ] 電話番号リンク（`tel:`）、メールリンク（`mailto:`）が正しいか
- [ ] ブラウザのコンソールにJSエラー・404（読み込み失敗）が出ていないか

## 6. WordPress特有（該当する場合）

- [ ] `WP_DEBUG`が本番でfalseになっているか
- [ ] デバッグ用の`var_dump()` / `print_r()`がコードに残っていないか
- [ ] パーマリンク設定が正しいか
- [ ] 管理画面の不要なデフォルトコンテンツ（Hello World記事等）が削除されているか
- [ ] ACFのフィールドが本番環境でも正しく同期されているか（acf-jsonの反映確認）
- [ ] 検索エンジンでのインデックスブロック設定（開発中サイトの「検索エンジンによるサイトの検索を回避する」設定）が、公開時にOFFになっているか

## 7. その他

- [ ] SSL（https）化されているか
- [ ] 常時httpsへのリダイレクト設定
- [ ] ブラウザタブのタイトルが適切か
- [ ] クライアントから預かった素材・原稿が最新版で反映されているか

## 出力形式

- コードやURLが渡された場合は、上記観点で実際に該当箇所を指摘する（推測で「たぶん大丈夫」とは言わない、確認できないものは「未確認」と明示する）
- 何も渡されず「チェックリストが欲しい」だけの場合は、上記をそのまま提示してよい
