# ビジュアルクラフト詳細（タイプスケール / 余白 / 階層 / 影 / 写真）

SKILL.md Phase 4 の数値ルールの根拠と生成手順。デザイントークンを最初に決めるとき・数値で迷ったときに読む。

## 1. タイプスケールの生成手順（乗算ルール）

1. 本文サイズを決める（Webは16pxが標準。情報密度の高いUIで14px、読み物主体で17〜18pxも可）
2. 比率を選ぶ（下表）。**マーケ系（LP・ブランド・コーポレート）は大きめ、一覧性重視（EC・アプリ）は小さめ**
3. 本文 × 比率^n で上下のサイズ列を生成し、キリのよい値に丸めてトークン化する

| 比率 | 名前 | 印象・用途 |
|---|---|---|
| 1.125 | Major Second | 情報密度の高いUI・管理画面・EC |
| 1.2 | Minor Third | 読み物・ドキュメント。落ち着き |
| 1.25 | Major Third | **標準**。コーポレート全般 |
| 1.333 | Perfect Fourth | LP・ポートフォリオ。訴求強め |
| 1.414 | Augmented Fourth | ヒーロー主導・ブランドサイト |

生成例（16px × 1.25、丸め後）: `12 / 14 / 16 / 20 / 25 / 31 / 39 / 49 / 61`

- **中間の値が欲しくなったらスケールに足すのではなく、既存の段のどちらかに寄せる**（段が増えるほど統制が消える）
- 実サイトの実測では、整ったサイトほど「大見出しだけ突出させ、その他は小さい固定サイズに抑える」構造が多い（例: 大見出し56px / 小見出し24px / 本文16px / ボタン・ラベル12〜14px）。**大きくする段は1〜2段に絞り、残りを揃える**のがメリハリの正体
- SP では h2 が 28〜32px 程度になるよう、上位段だけ `clamp()` で縮める（本文は固定でよい）

## 2. 流体タイポ（clamp）の安全則

```scss
font-size: clamp(2rem, 1rem + 3.3vw, 3rem);  // SP32px → PC48px
```

- **max ≤ min × 2.5 に収める**（WCAG 1.4.4 ズーム対応。`vw` はズームで変化しないため、振れ幅が大きいと200%拡大が成立しなくなる）。※MDNの「2倍以上」という記述は誤りで、正しくは上限側の制約
- 可変部は `vw` 単体でなく `rem + vw` の形にする（ズーム時に少しでも追従させる）
- **和文の本文には効かせすぎない**。本文は固定（または微小な振れ幅）にし、clampは見出し・ヒーローなど大きい文字だけに使う
- 計算機: fluid.style/type

## 3. 行間・行長

| 対象 | 行間 | 備考 |
|---|---|---|
| 大見出し（和文） | 1.2〜1.4 | 大きい文字ほど詰める。欧文なら1.1〜1.3 |
| 本文（和文） | 1.7〜2.0 | 小さい文字ほど開ける |
| ボタン・ラベル | 1〜1.2 | 折り返さない前提（折返しは design-verification #3） |

- 本文の行長は**全角35〜42字**（欧文なら45〜75字）。`max-width: 40em` 前後で制御
- サイズ違いのテキストを横に並べるときは**ベースライン揃え**（中央揃えにしない）

## 4. 余白システム

- スケール: `8 / 16 / 24 / 32 / 48 / 64 / 96 / 128 / 160`（8pxベース。4pxは微調整用に許可）
- 3層構造: **要素内 ＜ グループ間 ＜ セクション間**。この差がグルーピングを作る（罫線や枠より先に余白で区切る）
- セクション上下: PC 80〜160px / SP 48〜80px。`padding-block: clamp(4rem, 8vw, 8rem)` のような流体化も定番
- SP左右パディング: 16〜24px（狭いと読みにくくタップもしづらい）
- コンテンツ幅: 12列グリッド基準で設計すると、幅の違うコンテンツ（本文幅・カード幅・full-bleed）を同じルールで揃えられる
- **「画面を埋めなければならない」という思い込みを捨てる**。要素は必要な幅だけ取り、残りは余白でよい

## 5. 視覚階層の技法（Refactoring UI 由来）

- 階層の3レバー = **サイズ / ウェイト / 色コントラスト**。1つの要素に3レバー全部を使わない（大きく・太く・原色は過剰）
- **脇役を下げる**: 主役を装飾するより、周囲のコントラストを落とす。ナビ・フッター・補足が本文と同じ強度になっていないか
- ラベルと値は「ラベル: 値」の対で置かず、**値に語らせる**（例: 「在庫: 12」→「残り12点」）。ラベルが必要なら小さく薄く
- グレーは**5〜10段のスケール**をトークン化して使う（2〜3色のグレーでは階層が作れない。純グレーでなくブランド色相を微量含めると馴染む）
- 淡色背景上のグレー文字は「薄いグレー」でなく**背景色相に寄せた低コントラスト色**を作る（グレーを重ねると濁る）
- HTMLの意味階層と視覚階層は別物。h3でも主役なら大きく、h2でも補助なら控えめに（マークアップは semantics、見た目は role で決める）

## 6. 影のスケール

- 影は **5段のトークン**（例: `--shadow-1`〜`--shadow-5`）を定義し、段階以外を使わない
- 小さい影=浮き上がりの示唆（ボタン・カード）、中=ドロップダウン、大=モーダル。**階層が上のUIほど大きい影**
- 拡散する薄い影（環境光）＋輪郭近くの濃い影（直接光）の2枚重ねが自然に見える
- ボーダー（罫線）の代わりに 影 / 余白 / 背景色差 で区切れないか先に検討する（罫線だらけのUIは重く見える）

## 7. 写真の上の文字（4手法）

1. 全面オーバーレイ（黒/ブランド色 30〜50%）
2. 写真自体のコントラスト・明度を落として書き出す
3. 文字の裏だけグラデーション帯（下端キャプションの定番）
4. text-shadow（小さめ・広め。最終手段）

いずれも**コントラスト比の実測が最終判定**（Phase 5 / design-verification 1b-1）。
