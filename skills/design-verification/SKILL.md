# デザイン検証チェックリスト（AIスロップ検出）

design-taste で方向を決めて実装したページが、「AIが作った量産デザイン」に落ちていないかを検証する。

**線引き**: alt・meta・コンソールエラー等のコード品質は `pre-delivery-checklist`、アニメーションの実装作法は `animation-implementation` の担当。本スキルは**見た目とコピーのAIっぽさ**だけを見る。

**前提**: 検証はプロジェクトの design-taste の設定値（VARIANCE / MOTION / DENSITY と定義済みパレット）を正として行う。設定値が見つからない場合は先に確認する。

## 実行手順（必ずこの順番）

### STEP 1: 機械チェック（数える・grepする。目視の印象で判定しない）

コードにアクセスできる場合、以下を実際にカウント・検索して判定する。判定基準を満たさないものは ERROR として報告する。

| # | 項目 | 判定方法 | 基準 |
|---|---|---|---|
| 1 | 小ラベル（eyebrow）過多 | セクション見出しの上にある英字小ラベル（`text-transform: uppercase` + `letter-spacing` の小テキスト）を数える | セクション数 ÷ 3（切り上げ）以下 |
| 2 | CTA意図の重複 | ページ内のボタン・リンクCTA文言を全て列挙する | 同一意図のCTA（「お問い合わせ」と「ご相談はこちら」等）が別文言で並存していたら ERROR |
| 3 | CTAテキスト折返し | ボタン要素の文言長とmin/max-widthを確認 | SP幅でボタン内テキストが2行になるものは ERROR |
| 4 | レイアウトの単調さ | 各セクションのレイアウト型を分類する（全幅見出し型 / 画像左テキスト右 / その逆 / カードグリッド / リスト型 …） | セクション数の半分以上の型数があること（8セクションなら4型以上）。画像/テキスト交互のジグザグ3連続は ERROR |
| 5 | 3等分カードの多用 | 等幅3カラムのカード並びセクションを数える | 1ページ1回まで。2回以上は ERROR |
| 6 | アクセント色の氾濫 | SCSSの色トークン外で直書きされたカラーコードをgrep（`#[0-9a-fA-F]{3,8}` で `foundation/_variable.scss` 以外を検索） | design-taste のパレット定義にない色の直書きは ERROR |
| 7 | 角丸スケールの不統一 | `border-radius` の値の種類をgrepで列挙 | トークン化された段階（例: 4/8/16px + 9999px）以外の値は ERROR |
| 8 | グラデーションテキスト | `background-clip: text` の使用箇所を数える | 使うなら1ページ1箇所まで。大見出し複数への適用は ERROR |
| 9 | 純黒・純白 | `#000`（純黒）が文字色・背景色に使われていないかgrep | オフブラック系トークンに置換。※純白背景は design-taste の方針次第なので確認 |
| 10 | テーマの無計画な反転 | ダーク背景セクションとライト背景セクションの切替回数を数える | 意図（design-taste に記載）なしに2回以上反転していたら WARN |
| 11 | marquee過多 | 無限ループの横流し演出の数 | 1ページ1回まで（`animation-implementation` と共通ルール） |
| 12 | ダミー実績数値 | 「99.9%」「No.1」「10,000社」等の数値をgrepし、原稿・クライアント支給データと照合 | 裏付けのない数値は ERROR（薬機法・景表法リスクも `hearing-estimate` の観点で指摘） |

### STEP 2: AI判断チェック（症状ベース。「なんかAIっぽい」を言語化して指摘する）

以下の複合症状が出ていないかを見る。該当したら「どのセクションが・なぜそう見えるか」を必ず特定して報告する。

- [ ] **テンプレ・ヒーロー**: 中央寄せ見出し＋中央寄せサブテキスト＋中央CTA＋背景グラデの4点セット。VARIANCE 5以上の設定なら非対称構成（分割・オフセット・重なり）になっているべき
- [ ] **ヒーロー要素過多**: ファーストビューの要素が見出し・サブテキスト・CTA・ビジュアルの4つを超えて詰め込まれていないか。サブテキストが2文以上の説明文になっていないか
- [ ] **全セクション同一リズム**: 余白・見出しサイズ・構成が全セクションで同じで、ページに緩急がないか（DENSITY設定との整合を見る）
- [ ] **アイコンカードの羅列**: 写真・イラスト・実データを使わず、汎用アイコン＋短文のカードだけで特徴セクションを済ませていないか
- [ ] **コピーの同型反復**: 見出しが全て同じ構文（「〜で、〜を。」「〜する、〜へ。」等）で並んでいないか。英語キャッチコピー混在時は「—」（emダッシュ）の多用もAIサインとして見る
- [ ] **ダイヤル値との乖離**: design-taste の設定（例: VARIANCE 8）に対して実装が保守的すぎる／過剰すぎる箇所はないか
- [ ] **無難化（本プロジェクト固有・逆方向チェック）**: ポップ・高彩度の方向性なのに、彩度を落としグレー基調に寄せて「落ち着いた無難な仕上がり」に逃げていないか。禁止ルールの適用しすぎで個性が消えるのもスロップの一種とみなす

### STEP 3: 人間確認リスト（AIが判定できないもの）

- [ ] 参照サイト（reference DNA抽出元）と並べて見たときの印象の差
- [ ] ターゲット（採用担当者・見込みクライアント等）の目線で5秒見て何のサイトか伝わるか
- [ ] スクロール時のアニメーションの「気持ちよさ」（実機確認）
- [ ] フォント・写真素材のライセンスと商用可否

## 出力形式

1. **機械チェック結果**: 項目番号ごとに OK / WARN / ERROR と根拠の数値（「eyebrow 5個 / 上限3個」のように必ず数字で）
2. **AI判断結果**: 症状名＋該当セクション＋修正の方向性（「こう直す」まで書く。「検討してください」で終わらせない）
3. **人間確認リスト**: 今回該当するもののみ

- 修正提案は design-taste のダイヤル値・パレットと矛盾しないこと
- 「たぶん大丈夫」と言わない。カウントできなかった項目は「未検証」と明示する
